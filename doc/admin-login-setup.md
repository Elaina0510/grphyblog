# 内容后台登录指引 · Sveltia + GitHub 访问令牌（模块 11）· v0.0.3

> 面向：**会用网页点、不写代码**的你。全程在浏览器里做，大约 3~5 分钟。
> 目标：让线上 `https://grphyblog.pages.dev/admin/` 这个内容后台能登录、能改文字。
> 前置：仓库已建好并推上去、Cloudflare Pages 已能访问站点（见 `doc/account-setup.md` 第 2~4 节）。
>
> 这一版**取代**了原来的「注册 OAuth App / 填 client_id」流程。为什么换：
> 见下一节。你不用再注册任何 OAuth App，之前建的 `grphyblog admin` OAuth App 可以直接删掉。

> **本次改动说明（2026-09-29）**：后台原先**没有正文编辑器**——正文区只有当集合声明了一个名字必须正好叫
> `body`（就是「正文」这个字段，引擎靠这个名字把内容写进文件里 `---` 之后的那一块）的字段时才会被画出来，
> 当时没声明，所以正文整块是缺的、只能改标题那些小字段；**封面也只能打字、不能点选**。
> 这两处现在都补上了，用法以第 4~6 节为准（第 1 节里「没有上传入口」那句的准确读法也在那里：
> **能挑已经入库的图，但造不出新图**）；为什么非叫 `body`、照片到底是怎么被挡在生产之外的技术细节，
> 写在 `public/admin/config.yml` 顶部的注释里，不用你读。

---

## 0. 为什么从 Decap 换成了 Sveltia（一句话版）

Decap CMS 新版（3.x）的 GitHub 后端**删掉了「直接用 GitHub 账号登录」**，只认 Netlify 的登录代理；
本站托管在 Cloudflare Pages，那个代理回 404，点「Login with GitHub」必然报 Not Found。
Sveltia 是 Decap/Netlify CMS 的现役继任者，读同一份 `config.yml`、同一套内容仓库，
支持**粘贴一个 GitHub 访问令牌**直接登录——不需要任何第三方代理，也不需要自建服务器。

## 1. 先看这张表：谁做什么

| 步骤 | 谁做 | 做完长什么样 |
| --- | --- | --- |
| 1. 在 GitHub 生成一个访问令牌（PAT） | **你在浏览器点** | 一串 `ghp_...` 开头的字符，只显示一次，先存好 |
| 2. 把它 push 上线（本仓库改动） | 主 Agent（需你确认推送） | 线上 `/admin/` 出现 Sveltia 登录页 |
| 3. 打开后台、粘贴令牌登录 + 验收 | **你在浏览器点** | 进得去、能改文字、没有上传入口 |

⚠️ 令牌**不写进仓库任何文件**，只粘贴在你浏览器里（存在本机 localStorage）。

---

## 2. 生成 GitHub 访问令牌（照抄每一步）

1. 用**有仓库写权限的 GitHub 账号**（就是建 `Elaina0510/grphyblog` 那个号）登录 github.com。
2. 打开：**https://github.com/settings/tokens/new**
   （路径：右上角头像 → **Settings** → 左侧最底部 **Developer settings** →
   **Personal access tokens** → **Tokens (classic)** → 右上 **Generate new token (classic)**）
3. 表单从上往下填：

   | 输入框 | 填什么 |
   | --- | --- |
   | **Note**（备注） | `grphyblog admin`（认得出就行） |
   | **Expiration**（有效期） | 建议选 **90 days** 或 **Custom…No expiration**（见第 6 节安全提醒） |
   | **Select scopes**（勾选权限） | **只勾第一项 `repo`**（整行勾选框点一下即可，含子项）。别的都不勾 |

4. 拉到底点 **Generate token**。
5. 页面顶部出现一串 `ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`。点右边的 📋 复制。
   👉 **这串就是全部。它只显示这一次，关掉页面就看不到了**（忘了就回这里再生成一个、把旧的删掉）。

> **不要**勾 `admin:repo`、`delete_repo`、`workflow` 这些——后台只需要写内容，`repo` 一项就够。
> **不要**用 Fine-grained token：经典 `repo` 令牌与本仓库的公开仓 + 内容写权限口径最稳。

## 4. 登录 + 逐项验收（模块 11 · 门禁 D 线上部分）

1. 点 **使用访问令牌登录** → 出现一个输入框 → 粘贴第 2 节复制的 `ghp_...` → 确认/登录。
2. 进去后左侧能看到 **系列 / 随笔** 两个栏目 = 登录成功。
3. 逐项验收（**每项都该是"能改、能挑已入库的图、造不出新图"**）：

   | 验什么 | 怎么做 | 预期 |
   | --- | --- | --- |
   | 改文字 | 进 `系列 → 夜光 · 城市`（city-lights），把 **标题** 改一个字 → 右上 **发布/Publish** | GitHub 仓库多一条 commit（作者是你的账号），1~2 分钟后线上标题变了 |
   | 排序 | 同一页把 **排序权重（数字，越小越靠前）** 从 1 改成 2 → 发布 | 首页/系列列表顺序跟着变 |
   | 发布/撤下 | 把 **草稿开关** 打开 → 发布；再关掉 → 发布 | 打开后该系列从线上消失，关闭后回来 |
   | 选封面 | 打开一条**已经导入过照片**的条目（比如 `系列 → 夜光 · 城市`），找到 **封面（从本系列已入库照片里挑）** 这一栏，点它旁边的 **替换**（鼠标停在上面的名字是 Replace Image）→ 弹出标题为 **选择图片** 的窗口 → 点 **条目资源** 页签（打开就默认停在这个页签，列表里就是本条目 `photos/` 文件夹里已经入库的那些照片）→ 点一张 → 点 **插入** → 回表单点 **发布**。⚠️ **新建**的条目这一栏只有一个"将图片拖放到此处"的框、**没有** 替换 按钮——那是正常的：它的照片目录还没生成。先在 Git Bash 里跑 `npm run import -- --series <系列标识>`（随笔是 `-- --post <日期-标题>`）把照片导进去，再回后台打开这条，替换 按钮就出现了 | 全程**不用你打一个字**：路径由后台自己填好，栏里出现刚选的那个文件名（有的版本还会带一张小缩略图），1~2 分钟后前台卡片换图。窗口里的 **输入 URL** 页签已经被配置关掉了（配置项 `choose_url`：控制"能不能贴一个外部图片链接"），所以外链填不进来。**别的页签别用**：**全局资源**是整站的一个杂图夹（不放照片），后面四个（Lorem Picsum / Pexels / Pixabay / Unsplash）是示例图库服务 |
   | 写正文 | 表单**最下面**那一栏：系列叫 **正文（系列手记）**、随笔叫 **正文（随笔内容）**。在里面直接打字，上方工具栏有 段落样式、加粗、斜体、删除线、代码、链接、图片；想自己写 Markdown 就点编辑器**右上角**的 **以 Markdown 编辑**（同一份内容切成源码视图，再点一次切回来）→ 发布 | 字存进文件里 `---` 之后的正文区，**不会**变成 frontmatter 里多出来的一个字段。这一栏**留空也允许**（不想写字就不写） |
   | 插图 | 正文里的图**只能**在 **以 Markdown 编辑** 模式下手写一行引用，而这一行是导入脚本喂给你的：在 Git Bash 进项目目录跑 `npm run import`（系列）或 `npm run import -- --post <日期-标题>`（随笔），**跑完在最末尾**会打印出现成可粘的引用行，形如 `![说明](photos/night-01.webp)`（系列）/ `![说明](2026-09-21-morning-fog/photos/dawn-01.webp)`（随笔）。验收时手头没有新照片，就打开 `随笔 → 晨雾里的第一束光` → 点 **以 Markdown 编辑** → 另起一行贴 `![晨雾还没散](2026-09-21-morning-fog/photos/dawn-01.webp)`（这张已经入库，形状就是脚本会打印的那种）→ 再点一次切回富文本 → 发布 | 前台这篇出现该图，宽高和点开的大图（灯箱）都是构建时按同名的 EXIF 登记表 `photos.meta.json` 自动补的。⚠️ **路径整段复制、不要手打、不要改大小写**，否则构建找不到文件。工具栏那个 **图片** 按钮只有 拖拽 / **浏览**（上传）/ **粘贴图片** 三个入口，**没有**"从已入库照片里挑"的列表（引擎给不了），所以正文插图只能走 Markdown 模式 |
   | 上传兜底 | **这项不用真做**（做了会往仓库里塞一张没用的文件）：**选择图片** 窗口里确实还有个 **上传** 按钮，后台没有"只让挑、不让传"的开关，所以手滑是传得进去的 | 传进去的图不会被登记进 `photos.meta.json`，下一次构建（本地 `npm run build`，Cloudflare Pages 用的也是它）会先跑 `scripts/check-image-sources.mjs`，日志里打一行 **`[check-image-sources]`** 红字点名那个文件并**失败**（规则 R1/R3/R5）——也就是进不了线上。删掉它（或让主 Agent 删）、再用 `npm run import` 正规入库就绿了 |
   | 无 sidecar 编辑口 | 看左侧栏目与条目列表 | 找不到 `photos.meta.json` 或 `photos/`，它们不是可编辑条目 |

4. 全绿 = **模块 11 达成**。有任何一项不对，先按第 5 节对号，再把现象贴回给主 Agent。

> 建议验收后，把刚才改的标题/排序/正文**改回原值再发布一次**，或让主 Agent 直接回滚那条测试 commit。
>
> 两种**正常现象**，不用管、也不用手工改回去：
> ① 存进文件的路径形状——系列是 `photos/night-01.webp`，随笔是 `2026-09-21-morning-fog/photos/dawn-01.webp`
> （随笔的 `.md` 是平铺文件、插图夹与文件同名，所以多一层目录名），前台构建对这两种写法都认。
> ② 保存后 frontmatter（文件开头 `---` 之间那一段参数）可能被后台**重排**：键的顺序会变，
> `tags: [风光, 晨雾]` 这种一行写完的写法会被改写成多行列表写法。不影响构建。

## 5. 出问题对照表

| 现象 | 大概率原因 | 怎么办 |
| --- | --- | --- |
| `/admin/` 空白或 404 | Pages 还没构建完；或访问的是 `/admin`（没斜杠） | 等 1 分钟强刷；地址补成 `/admin/` |
| 登录页仍显示 "Login with GitHub" 且点了报 Not Found | 浏览器缓存了旧版 `/admin/`（旧 Decap 页） | 硬刷新 `Ctrl+Shift+R`；或无痕窗口打开；确认第 3 步已 push 且 Pages 构建成功 |
| 粘贴令牌后报 **401 / Bad credentials** | 令牌复制不全、或已过期/被删 | 回第 2 节重新生成一个，整串复制 |
| 登录进去但保存报 **403 / Needs more permissions** | 该令牌没勾 `repo`，或该账号对仓库没有写权限 | 重新生成并勾上 `repo`；确认登录的是仓库属主账号 |
| 左侧没有「系列 / 随笔」，或看不到已有条目 | 嵌套集合的目录层数（`nested.depth`）与仓库形态没对上 | 只改 `public/admin/config.yml` 里 series 的 `depth: 2`：先试 `1` 再试别的，每次 push 后强刷；**哪一档生效告诉主 Agent**，它会钉进配置与单测 |
| 保存后网站没变 | Pages 构建失败或在排队 | Pages → Deployments → 看最新那条 **Build logs**；若日志出现 `[check-image-sources]` 红字，说明有人往 public/ 塞了非脚本图片，删掉那张图再 push |
| 表单**最下面**那一栏「正文（系列手记）/ 正文（随笔内容）」整块不见了 | 后台配置文件 `public/admin/config.yml` 里那个名字必须正好是 `body`（=「正文」）的字段被删掉了——正文区只有声明了它才会出现，少一块是整个区域没了，不是"输入框变小了" | 你不用改代码：把现象（哪个栏目、截图）贴回给主 Agent，让它把 `body` 字段加回去并 push；之后 `Ctrl+Shift+R` 强刷一次再看 |
| 点 **发布/Publish** 时报 **409 / 412**，或弹提示说版本冲突 | 你编辑这段时间里，别人（或主 Agent）先推了一条 commit，你手上那份后台副本已经过期 | `Ctrl+Shift+R` 强刷后台页面 → 重新把刚才的改动做一遍 → 再发布；还是失败就把报错原文截图给主 Agent |
| 构建日志出现 **`[check-image-sources]`** 红字（点名一个文件名） | 有人用了 **选择图片** 窗口里的 **上传** 按钮：传进去的图不会登记进那条内容的 EXIF 登记表 `photos.meta.json`（只有 `npm run import` 会登记）。落在条目 `photos/` 里触发的规则是 R3，落在别处是 R1，落到 `public/` 是 R5 | 按红字里的路径**删掉那个文件**（不好删就交给主 Agent），再用 `npm run import`（随笔加 `-- --post <日期-标题>`）正规入库一次 → 重新构建，红字消失即通过 |
| 封面在后台明明选了，前台卡片却不显示 | 路径是手打进去的、打错了（多一个 `/`、少一层目录名、大小写不符），仓库里没有这个文件 | 回 **封面** 栏点 **替换** → **条目资源** 页签重选一次那张图，让后台自己写路径，**别手打** |

## 6. 撤销 / 换域名 / 安全红线

- **换电脑、令牌泄漏、不想再让它登录**：GitHub → Settings → **Developer settings** →
  **Personal access tokens** → 找到 `grphyblog admin` → **Delete（撤销）**。网站前台不受影响（静态）。
  下次要再进后台，就再生成一个。
- **换域名**（以后绑自定义域）：改 `public/admin/config.yml` 的 `site_url` / `display_url`
  与 `astro.config.mjs` 的 `site`，两处域名必须一致；令牌与本流程无关，不用重发。
- **安全红线**：
  1. 仓库里**永远不出现任何令牌**（`.env` / config / README 都不行）；令牌只活在浏览器 localStorage。
  2. 经典 `repo` 令牌权限不小（等于该账号对仓库的读写），**设个有效期**、不用时能一键撤销，是给自己的兜底。
  3. 后台**能改文字、能从已入库的照片里挑**（封面点 **选择/替换 → 条目资源**，正文在 **以 Markdown 编辑** 里引用），
     但**造不出新图**：**选择图片** 窗口里那个 **上传** 按钮传进来的文件，不会被登记进条目的 EXIF 登记表
     `photos.meta.json`（只有本地 `npm run import` 会登记），而 `npm run build`（**也就是 Cloudflare Pages 的构建命令**）
     第一步先跑 `scripts/check-image-sources.mjs`，会打一行 `[check-image-sources]` 红字点名那个文件并**失败**
     （规则 R1/R3/R5）——所以传上来的东西进不了生产。兜底处理：删掉那个文件（或让主 Agent 删），
     再用 `npm run import` 正规入库。`photos/` 与 `photos.meta.json` 本身不经后台编辑。
  4. Sveltia 走 CDN 且**版本已锁**（`public/admin/index.html` 里是 `@sveltia/cms@0.221.0`，不是 latest）；
     升级 = 手动改那一行 + 线上再登录验一次。
