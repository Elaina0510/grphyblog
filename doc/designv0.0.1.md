# 个人摄影博客 · 设计文档

状态：已逐节确认（2026-09-23），并按审查修订（同日）：**照片一律本地脚本压缩入库，原图不上传，`/admin` 仅文字操作**。视觉风格由后续设计阶段（设计 skill）接管，本文只锁定结构、流程与技术决策。→ **视觉设计阶段已完成（2026-09-23）**：方向、规范与首页视觉稿见第 10 节。

## 1. 定位与目标

- 核心目的：**个人作品陈列**——照片为主角，自己记录与分享，不追求流量。
- 内容形式：**系列 + 文字混合**。既有成组的作品系列，也有少量带拍摄手记的记录。
- 发布预期：高频发布，两年内照片上千张。
- 用户技术背景：能照说明装软件、跑命令、用 git/网页提交，不写代码；代码与部署问题交给 AI。
- 成功标准：文字与页面管理全程在浏览器完成；照片发布只需把文件丢进文件夹+一条本地命令；手机上看图体验流畅；仓库与构建长期可持续。

## 2. 内容结构与数据模型

所有内容以 Markdown 文件形式存于 Git 仓库，两种内容单元：

**系列（Series）**
- 一个系列 = 一个文件夹：`src/content/series/<系列标识>/index.md` + 照片资源
- frontmatter 字段：标题、日期、封面图、标签（城市/风光/人像等）、排序权重、草稿标记
- 正文可选写拍摄手记，也可以只有照片

**单篇随笔（Post）**
- `src/content/posts/<日期-标题>.md` + 同名资源文件夹放图
- frontmatter 字段：标题、日期、封面、标签、草稿标记

**站点级内容**：首页精选区（手动挑图）、关于页（简介+社交链接）。

**扩展原则**（应"方便后续加功能"的要求）：新功能以"新增 collection 类型"方式加入，不改现有结构。

## 3. 技术架构与目录

```
grphyblog/
├─ src/
│  ├─ content/          # 内容层：series/ 与 posts/（Markdown + 图片）
│  ├─ components/       # 展示层：纯 UI 组件（图框、导航、照片网格…）
│  ├─ layouts/          # 页面骨架：首页/系列页/文章页/关于页
│  └─ styles/           # 设计变量集中一处（视觉设计阶段只改这里+组件）
├─ scripts/
│  └─ import-photos.mjs # 工具层：raw/ → 压缩+缩略图+EXIF → 写入系列资源夹
├─ public/admin/        # Decap CMS 前端 + config.yml
├─ astro.config.mjs     # 构建与图片优化参数集中于此
└─ raw/ thumbs/         # 本地素材区，.gitignore 排除，不进仓库
```

**四条边界**
1. 内容与代码分离：新增系列/随笔只是加文件，不碰代码。
2. 图片规格集中在构建配置：改清晰度/换格式只改一处参数重构建。
3. 图片路径统一由一个 `imageUrl` 工具函数生成：日后整体迁 R2/图床只改这一个文件（预留 B 方案退出路径）。
4. 新内容类型 = 新 collection 配置 + 新 schema，不动现有结构。

**部署链**：GitHub 仓库 → Cloudflare Pages 自动构建（push 即上线，免费档带宽不限）。Decap CMS 经 GitHub OAuth 登录，保存即提交。回滚 = 在 GitHub revert 一次提交。

**后台鉴权机制（已定）**：GitHub OAuth App（implicit grant，`repo` scope），注册由 AI 出步骤、用户在 GitHub 网页上点完成；仓库为 public（网站本就公开），仅持 OAuth 授权且对仓库有写权限的账号能经 `/admin` 提交。不引入 Netlify 等第三方代理。

**技术栈**：Astro 5+（实施时取当时稳定大版本；Content Collections + 类型安全 schema）· sharp（脚本压缩）· exifr（EXIF）· Decap CMS · Cloudflare Pages · Node LTS。纯静态输出，无前端框架依赖。

**CMS 风险备案**：Decap CMS 于 2026-09 核实仍活跃维护；若未来停维，改用兼容替代 Sveltia CMS，影响面仅 `public/admin/` 一个目录，内容仓库与构建不受波及。

## 4. 照片入库与发布流程

**本地批量导入：`npm run import`**
1. 相机导出照片丢进 `raw/`。
2. 脚本对每张新图自动：
   - 压成展示版（2560px 长边 WebP，约 300~600KB）+ 缩略图（800px 长边 WebP，约 30~60KB）；
   - 读 EXIF（机型/镜头/焦距/光圈/快门/ISO/日期）写入照片元数据 sidecar（系列文件夹内 JSON）。sidecar 由脚本生成与维护，只供灯箱展示读取，不经后台人工编辑。
   - 产物写入指定系列：`npm run import -- --series <系列标识>`；缺省时脚本交互式询问目标系列，系列不存在则当场新建（以草稿状态入库，在后台补写手记后去掉草稿标记发布）；原图原地留在 `raw/`，不进 Git。
3. 本地预览确认 → `git push` → 自动构建上线。

`thumbs/` 作为脚本缩略图输出暂存区（同样不进仓库，最终产物在内容文件夹内）。

**2026-09-24 补拍板（随笔插图同通道）**：随笔插图同样出自导入脚本——`npm run import -- --post <日期-标题>` 将展示图/缩略图/sidecar 写入随笔同名资源文件夹，`.md` 不存在则生成草稿骨架。由此"所有照片都出自脚本"对随笔同样成立，§5"点击任意照片→灯箱"与拍摄单在系列/随笔两处口径一致；原"系列不存在则当场新建"逻辑对随笔同理。

**网页后台 `/admin`（Decap CMS）——仅文字操作**：新建系列条目、写手记、编辑文字、调排序、从**已入库照片**中选取封面（image 字段配 `media_library` 只读引用，禁止上传新文件；全局关闭后台文件上传）。Decap 的上传是"原样提交"且浏览器压缩需自研组件，故照片通道不经过后台。EXIF 信息条也因此天然完整——所有照片都出自脚本。

**原图策略（已拍板）**：相机原图不入仓库、不上传云端仓库，仅存本地 `raw/`，**定期备份由用户自行负责**（移动硬盘/网盘）。

## 5. 页面清单与浏览体验

v1 共 6 类页面，全部静态生成：

| 页面 | 路径 | 内容 |
|---|---|---|
| 首页 | `/` | 精选区（手动挑选入口图）+ 最新系列/随笔 |
| 系列列表 | `/series/` | 系列卡片（封面+标题+日期+张数） |
| 系列详情 | `/series/<标识>/` | 头图 → 拍摄手记 → 照片流 |
| 随笔列表/详情 | `/posts/…` | 时间倒序；文字为主、插图为辅 |
| 关于 | `/about/` | 简介 + 社交/联系链接 |
| 404 | — | 引导回首页 |

**照片查看（功能层面）**
- 点击任意照片 → 全屏灯箱；左右键/滑动切换，Esc 退出。
- 灯箱内可展开 EXIF 信息条。
- 移动端：缩略图双列起步，手势滑动切图。

**v1 暂不做**（结构留扩展位）：标签页、站内搜索、RSS、编号分页页（长列表用滚动追加渲染，见第 6 节，二者不要混淆）。

## 6. 性能预算与仓库体积

- 首页与系列页 Lighthouse Performance ≥ 90（移动端模拟）。
- 缩略图 ≤ 80KB/张；展示图 ≤ 800KB/张；全部懒加载 + 显式宽高占位防布局抖动。
- 单页照片 > 30 张时分批渲染（IntersectionObserver 追加）。
- 仓库体积：进仓库的只有 Markdown + 压缩产物，1000 张**工作树**估算 400~600MB。注意 git 历史只增不减（换图/重压会额外保留旧版本，实际 `.git` 约为工作树的 1.5~2 倍）。触发线：工作树或 `.git` 超 ~1GB 时，执行 `imageUrl` → R2 迁移（方案 B），或先用孤儿分支重建一次历史续命。每年底复核增长曲线。

## 10. 视觉设计决策（2026-09-23 定稿）

**视觉方向（用户锁定）**：摄影 zine · 自印书——整站是一册摊开的自印摄影书，首页翻"跨页"而非扫缩略图网格。推导过程与四方向对比存档于 surface brief。

**已拍板的视觉事实**：
- 站点语言：中文为主 + 英文点缀；个人标识：**柚**（中文）/ **Justyou**（拉丁），并用方案已在视觉稿验证。
- 色系：纸白 `#F2F1EC` + 墨 `#26241F` + 唯一强调朱砂 `#A03B28`（≤5% 面积，只做"盖章级"语义）+ 灯箱夜底 `#191816`；照片承担全部色彩。
- 字体：思源宋体（书名/章题，900）· 思源黑体（正文 16.5px/1.9）· Courier Prime（页码/EXIF/微标签）。中文竖排是结构件（书脊导航、章题、开场书名）。
- 版式：左缘 76px 固定书脊 + 1280 容器；开场跨页 1/3 文字 · 2/3 图版；系列=章节题行 + 满版跨页 + 左右对置手记；系列列表=目次点线行；关于=版权页（colophon）；章间留白 clamp(72px,12vh,128px)。
- 组件三件套：图版（落纸影 + zoom-in）· 页码片（帧号）· 拍摄单（EXIF 说明签，示例值以朱砂 ※ 标注）。
- 灯箱（签名交互）：夜底全屏，图版 ↔ 灯箱像 View Transition 形变，拍摄单从页边滑入，←→/滑动切帧、Esc 合页，开启时背景 inert、换帧 aria-live。
- 动效：全站一条缓动曲线 cubic-bezier(.16,1,.3,1)，入场 rise 一次编排；prefers-reduced-motion 全部直出。
- 性能对齐：图版显式宽高、懒加载、单列/跨页结构与第 6 节预算同构；视觉稿图片即 2560px 长边展示版规格。
