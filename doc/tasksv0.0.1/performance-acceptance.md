# Tasks · 性能与验收（performance-acceptance）

> 版本 v0.0.1 ｜ 来源：designv0.0.1.md §6、§7 里程碑 5 ｜ 依赖：全部模块（末位执行）
> 目标：用真实数据过一遍性能预算与完整发布流程，手机+电脑双端验收；固化仓库体积监控口径。

## 最小任务清单

- [ ] 1. 体积抽检脚本（可选 `npm run audit:size`）：遍历内容目录断言 缩略图≤80KB、展示图≤800KB，超标列表打印
- [ ] 2. 图片审计：全站 `<img>` 显式宽高 + `loading="lazy"` 无一遗漏（构建后抽查 HTML）
- [ ] 3. 分批渲染实测：造一个 >30 张的测试系列，确认 IntersectionObserver 追加生效、滚动无白屏
- [ ] 4. Lighthouse（移动端模拟）：首页 ≥90、系列详情页 ≥90；不达标则按报告逐项修（优先字体与图片）
- [ ] 5. 完整流程演练 A（照片）：真拍一批图 → 丢 `raw/` → `npm run import` → 本地预览 → 后台补手记去掉 draft → push → 线上可见
- [ ] 6. 完整流程演练 B（纯文字）：仅 `/admin` 改文字/调序/换封面 → 自动发布
- [ ] 7. 手机端体验：真机过 灯箱手势切帧、View Transition 形变、双列缩略图、`prefers-reduced-motion` 开关各一遍（并入里程碑 4 尾货）
- [ ] 8. 可访问性抽查：键盘-only 走全站、屏幕阅读器读帧号/EXIF、对比度（纸白底墨字）
- [ ] 9. 仓库体积基线：记录当前工作树与 `.git` 大小写入 `doc/repo-size-log.md`，标注 ~1GB 触发线 → R2 迁移/孤儿分支重建两个预案入口
- [ ] 10. 结题清单：对照 §9"明确不做"与 §5"v1 暂不做"（标签页/站内搜索/RSS/编号分页页）两份清单逐项确认没多做；§1 成功标准逐条打勾

## 验收标准

- [ ] §6 全部预算项通过（数值达标，不是"差不多"）
- [ ] 用户本人（不写代码）能独立完成演练 A + B 全流程，无需 AI 临场指挥
